# v0.2.0 - Historical Private Pre-Public Release

This preview release turns the crossfade refinement from the trip-hop trance test
run into the official CLI behavior.

## Added

- Default `active-cue` mix policy for long MP3 masters.
- Per-track cue analysis for generated near-silence, quiet heads, active starts,
  quiet tail trims, and manifest warnings.
- CLI controls:
  - `--mix-policy active-cue|strict`
  - `--quality-gate warn|fail|off`
  - `--cue-threshold-db`
  - `--silence-threshold-db`
  - `--cue-padding-seconds`
- Synthetic tests for trimming generated dead air before crossfading.

## Why it matters

Stable Audio generations can include dead air or slow heads/tails. A strict raw
crossfade can technically overlap tracks while still sounding like there is a
gap. The default policy now trims near-silent dead air, trims quiet tails that
would waste overlap time, and starts incoming tracks from an active cue point,
while keeping the first track free of global fade-in and the final track free of
global fade-out.

## Compatibility

Use `--mix-policy strict` for exact raw-boundary behavior from earlier releases.

This release still does not include Stable Audio model weights, generated music,
or any license promise for user-generated outputs.
